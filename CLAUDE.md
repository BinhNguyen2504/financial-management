# Claude Code notes — Financial Manager

Personal finance PWA (Vietnamese UI, VND): Next.js 16 + React 19 + Tailwind 4, Supabase Auth, PostgreSQL with RLS, Vitest + Playwright. Product docs, UI copy and `docs/` are Vietnamese; keep that language there. Reply to the user in Vietnamese when they write Vietnamese.

`AGENTS.md` (imported above) is the shared rule set for all coding agents and is regenerated by `next dev`; never edit it for Claude-only guidance — put that here or in `.claude/`.

## Commands

Node must be 22.12+. The Bash tool starts a fresh shell per call and the machine default is Node 18, so prefix every npm command: `source ~/.nvm/nvm.sh && nvm use 22 >/dev/null && npm run …`.

| Command                                    | Purpose                                                                                       |
| ------------------------------------------ | --------------------------------------------------------------------------------------------- |
| `npm run check`                            | CI gate: lint → check:architecture → format:check → test → typecheck → build                  |
| `npm test` / `npx vitest run tests/<file>` | Unit tests (excludes `*-postgres.test.ts`)                                                    |
| `npm run test:db`                          | Isolated local PostgreSQL integration (needs `pg_config`/`PG_BIN`; never uses `DATABASE_URL`) |
| `npm run test:e2e`                         | Browser tests on isolated production build + Auth double                                      |
| `npm run dev`                              | http://127.0.0.1:3000 (works without `.env`: landing + login-setup state)                     |
| `npm run data:preview`                     | Local review dataset (`review@example.test` / `12345678`)                                     |

Before writing Next.js code, read the matching guide in `node_modules/next/dist/docs/` (this Next version differs from training data).

## Layers (enforced by `scripts/check-architecture.mjs`)

`domain/<module>` pure TS (imports only `domain/*` and `zod`; BigInt money) → `application` (preview/command/version/idempotency; imports only application/domain) → `server` (Auth, HTTP, SQL repos, RLS) → `features/<module>` (editor/workspace UI) + `app` routes. `i18n/report-exports` translates CSV from domain results. Client components must not reach `server/`, `application/`, `server-only` or Node builtins at runtime; no runtime import cycles. Module shape and editor/workspace split: `docs/11-source-maintenance.md`.

## Invariants — do not "simplify" these away

- Money is BigInt / decimal strings, never floats. Gold units, stored data, backup JSON and CSV number formats stay unchanged.
- Two fingerprint algorithms differ on purpose: command fingerprint uses `localeCompare`, backup fingerprint uses character-order comparison. Do not merge them.
- DB lock order is global (Expenses before Funds; restore keeps its own order/transaction). Repositories keep their own owner/schema checks.
- Every private page's default function directly `await pageAccess(path)` and returns the denial; the architecture check rejects awaits inside nested callbacks. Public `/` must stay accessible with any session state.
- `src/app/experience.css` imports the parts in `src/app/styles/experience/` in a fixed order; moving a rule must preserve cascade and specificity.
- Per-module HTTP wrappers/error classes and route behaviour (Content-Length policy, streaming backup parser) are intentional.
- Landing preview data is fixed and illustrative; never read financial APIs or signed-in data there.

## Safety boundaries

- Never read or edit `.env.local`, `Notion/`, `imports/`, `backups/` (private financial material, git-ignored).
- Never connect to Supabase cloud or run `data:import`, `data:funds:import`, `data:goals:review`; seeds/migrations are prepared as files for the owner to run.
- Migrations: add new files under `supabase/migrations/` only; do not edit applied ones.
- Do not claim bank sync, offline entry, net-worth reporting, or cloud/device validation that the docs do not already support.

## Workflow

1. Product/UI/auth changes → follow the `docs-sync` skill: update `src/features/catalog.ts`, landing/preview, README and affected `docs/features/*` in the same change, keep dated validation history, and finish with a "documentation review" line in the report.
2. Run `/check` (skill) before reporting done; report failures verbatim.
3. UI changes → `ui-verify` skill (dev server + Playwright MCP; screenshots go to git-ignored `artifacts/playwright/`).
4. New finance module → `new-module` skill. Review risky diffs with the `invariant-reviewer` subagent.
5. Path-scoped rules live in `.claude/rules/`; shared design skills in `.agents/skills/` are symlinked into `.claude/skills/` (single source with Codex).
